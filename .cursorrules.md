
# Reglas Críticas del Agente
El Comportamiento de la IA al programar

**Propósito:** Inyecta restricciones técnicas inmediatas en el IDE. Es el "Linter de Intención" que previene la deuda técnica.

- Antes de iniciar, lee AGENTS.md para entender la misión.
- Consulta siempre .agent/rules/ui-style.md antes de crear componentes UI.
- Respeta estrictamente la Arquitectura Hexagonal definida en el PRD.
- No modifiques esquemas de base de datos sin generar una migración en /supabase/migrations/.

## **1. Restricciones de Arquitectura Hexagonal (Img 2)**

* **Domain**: Lógica pura, sin dependencias externas. No importar nada de @/infrastructure.
* **Application**: Contiene los use-cases. Coordina el flujo pero no conoce la implementación de la DB.
* **Infrastructure**: Aquí viven los adaptadores (Supabase, Stripe, APIs). Es la única capa que puede tocar servicios externos.
* **Modules**: Componentes SaaS independientes (CRM, ERP). Deben ser autocontenidos.

## **2. Estándares Next.js 15 & React 19**
* **Server First**: Todos los componentes son React Server Components (RSC) por defecto. Usa "use client" solo para interactividad mínima en hojas finales del árbol.
* **Data Fetching**: Usa Server Actions para mutaciones. Evita API routes internas a menos que sean para webhooks externos.
* **TypeScript**: strict: true. Prohibido el uso de any. Define interfaces para cada prop.

## **3. Reglas de Seguridad Supabase (Pool Model)**

* **RLS Obligatorio**: No crees tablas sin su correspondiente política de aislamiento por tenant_id.
* **Fórmula de Integridad**: Access = (request.auth.uid() <> Null)
* **Secrets**: Nunca escribas API Keys en el código. Usa @/.env.

## **4. Verificación Agéntica**

* Cada tarea debe terminar con una prueba exitosa en el terminal o navegador.
* Si el agente falla 2 veces en el mismo error, debe leer la documentación en docs/reference/ antes de intentar una tercera vez.

## **5. Directiva de herencia**    
**Directiva de Contexto**: Antes de operar en cualquier subdirectorio, busca y lee el archivo AGENTS.md local. Estas reglas locales tienen prioridad absoluta sobre las instrucciones globales para las tareas realizadas dentro de este ámbito específico.

## **6. Regla Anti-Overdesign**

- Ningún efecto visual debe interferir con legibilidad o velocidad.
- Si un efecto no aporta claridad funcional, debe eliminarse.
- Prioridad: claridad > estética > animación.
